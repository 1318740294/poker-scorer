# 德州记分桌（poker-scorer）

微信小程序 · 现金局共享记分桌 MVP。无牌面、无荷官发牌；街次仅为标记。筹码以视觉为主，线下自行结账。

产品决策见仓库外方案文档；本实现不发明冲突规则。

## 功能（MVP）

- 房主建房 / 玩家房号加入，5–12 座，点空位入座
- 自动扣 SB/BB；按座位行动；翻后枪口起→小盲
- 街次自动推进；首次最低加注 = BB，之后 raise 至少 ×2
- 快捷：底池 1/4、1/3、1/2、自定义 bb、All-in
- 边池自动拆；摊牌后房主点各池赢家
- 自由 Rebuy；本手结束后离桌
- 整场共享 3 张延时牌（每次 +30s）；超时由房主强制 fold /（无人下注时）check
- 断线不暂停倒计时；房主纠错撤销上一步
- 椭圆牌桌 HUD：形象、深度、倒计时

未做：推筹码物理、历史回放、语音、多桌、比赛涨盲。

## 在微信开发者工具中打开

1. 安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. **导入项目**：目录选择本仓库根目录；AppID 填你的小程序 AppID（或测试号）。  
   - 打开后把 `project.config.json` 里的 `"appid": "touristappid"` 改成真实 AppID。
3. 确认 `miniprogramRoot` = `miniprogram/`，`cloudfunctionRoot` = `cloudfunctions/`（已写在 `project.config.json`）。

## 开通并启用微信云开发

1. 开发者工具顶部 **云开发** → 开通环境（记下 **环境 ID**）。
2. 在开发者工具中把云环境关联到项目。`miniprogram/app.js` 默认使用 `wx.cloud.DYNAMIC_CURRENT_ENV`；若初始化失败，再改成你的环境 ID 字符串。
3. 云开发控制台 → **数据库** → 按 `database/schema.md` 创建集合：
   - `rooms`（必需）
   - `users`（可选）
4. 集合权限建议：**所有用户不可读写**（仅云函数可读写）。客户端用 `watch` 读 `rooms` 时，可改为「仅创建者可读写」不满足多人桌，因此 MVP 推荐：
   - 读权限：所有用户可读，仅管理端/云函数可写；或
   - 自定义安全规则：`read: true, write: false`（写全部走云函数）。
5. 在开发者工具 **cloud函数** 面板：
   - 右键 `cloudfunctions/login` → **上传并部署：云端安装依赖**
   - 右键 `cloudfunctions/api` → **上传并部署：云端安装依赖**
6. 编译运行。真机预览需同一云环境，并保证基础库 ≥ 2.2.3。

## 操作路径简述

1. 首页设昵称/形象 → **创建房间** 或输入房号 **加入**。
2. 候场页点空位入座；房主设盲注 → **开一手**。
3. 牌桌页按行动栏操作；超时后房主点强制弃牌/过牌。
4. 摊牌后房主为每个边池点赢家 → **确认派彩** → **下一手**。

## 单人本地调试（没有朋友一起测）

一人也能把「建房 → 入座 → 开一手 → 行动 → 摊牌」跑通。下面按「应用实际支持」说明，不依赖虚构功能。

### 1. 先跑规则引擎（无需微信）

```bash
node scripts/test-engine.js
node scripts/test-openid.js
```

覆盖扣盲、行动、边池、多身份入座，以及云函数 `getOpenId` 对 `dbg_*` 的门禁；UI / 云函数联调仍需开发者工具。

### 2. 推荐：首页「调试 · 单人多身份」（仅 develop）

**合并本修复后，必须在开发者工具重新上传并部署 `login` 与 `api` 云函数**，否则伪身份不会生效。

仅在微信开发者工具、`envVersion === 'develop'` 时首页底部会出现 **调试** 面板。按下面点击路径操作（Host 建房时会**自动坐到 0 号位**，无需再点空位）：

1. 首页底部 **调试 · 单人多身份** → **开启** → 点选 **Host**（昵称会变成 Host）。
2. 点 **创建房间** → 进入候场：应看到 **当前身份 · Host**，且 **1/9 人**、0 号位已坐 Host。**点房号复制**（或记住 6 位码）。
3. 左上角返回首页（不要清缓存）→ 调试面板点选 **玩家2** → toast「身份 dbg_p2」。
4. 把房号粘贴进输入框 → **加入** → 候场应显示 **当前身份 · 玩家2**，且 Host 仍在 0 号位。
5. 点另一个 **空位** 入座 → toast「已入座 · 玩家2」→ 人数变为 **2/9**，两个座位昵称不同。
6. 再回首页切回 **Host** → 用房号 **加入**（或从最近页回到该房）→ **开一手** → 牌桌按当前身份行动。

可选：继续用 **玩家3 / 玩家4** 占更多座。开一手至少需要 2 人已入座。

实现要点：客户端把 `dbg_*` 传给云函数；云端仅在开发者工具来源（`SOURCE=wx_devtools`，或部分工具省略 SOURCE）且前缀为 `dbg_` 时采用伪身份。**真机 / 体验版 / 正式版（`SOURCE=wx_client` 等）一律忽略 `dbg_`，无法伪造。** 也可在云函数环境变量设 `ALLOW_DEBUG_OPENID=1` 作显式开关（仍建议仅开发环境使用）。

候场页顶部的 **当前身份** 用于确认切换是否生效；若仍显示 Host 却想以玩家2 入座，请回首页重选身份后再加入。

### 3. 官方多账号 / 多编译模式（不改代码）

若不想用调试面板，可用开发者工具自带能力：

- **添加编译模式**：不同模式可配不同启动参数；配合清存储 / 不同测试号观察隔离。
- **多账号调试 / 第二个模拟器身份**（视开发者工具版本菜单而定）：用另一身份加入同一房号。
- **两台真机预览**：各用自己的微信扫码，一人建房、一人加房。

注意：同一真实 openId 只能占一席；不能靠「房主点空位替别人坐下」——入座始终绑定当前登录身份。

### 4. 单身份时房主能测什么

只有一个 openId 时：可建房、自己入座、改盲注、改自己筹码；但 **开一手需要 ≥2 人已入座**，因此无法单身份完整打一手。超时强制行动、纠错撤销、摊牌点赢家等房主工具，在有第二人入座后可用。

### 5. 建议最小联调路径

1. `node scripts/test-engine.js` 与 `node scripts/test-openid.js` 变绿  
2. **重新上传** `login` + `api` 云函数，并确认 `rooms` 集合已建  
3. 按上文第 2 节点击路径占满 2 席 → 开一手 → 走完行动与派彩
